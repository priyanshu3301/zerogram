# Encryption Model

Zerogram is designed around a strict zero-knowledge security model. All file contents and metadata are encrypted locally on the device before being transmitted to Telegram.

## Core Cryptography

We use [Google Tink](https://github.com/google/tink) to handle all cryptographic operations, ensuring we use peer-reviewed, industry-standard primitives rather than rolling our own crypto.

- **Algorithm**: `AES256-GCM-HKDF` (Streaming AEAD)
- **Chunk Size**: 1 MB
- **Key Storage**: The Master Vault Key is encrypted by Android's hardware-backed Keystore and stored in `EncryptedSharedPreferences`.

## The Vault Key
When the user creates a vault, a highly secure AES-256 key is generated by Tink. This key is the **only** way to decrypt the files stored on Telegram. 

- If the user uninstalls the app or clears the app data, this local key is destroyed. 
- Without this key, the data stored on Telegram is computationally impossible to recover.
- **Note**: Currently, vault key export/import is under development. If you lose your device, your vault data cannot currently be recovered.

## File Upload Flow
1. User selects a file to upload.
2. `CryptoManager` creates an encrypted output stream targeting a temporary cache file.
3. The plaintext file is read and streamed through Tink's `StreamingAead`, writing ciphertexts in 1MB chunks to the cache file.
4. Once encryption is complete, the encrypted cache file is uploaded to Telegram via TDLib.
5. The local cache file is securely wiped.

## File Download Flow
1. File is downloaded from Telegram to the local cache via TDLib.
2. `CryptoManager` opens a decrypting input stream over the encrypted file.
3. The stream is read, authenticating the GCM tags on the fly.
4. The plaintext is streamed directly to the user's `Downloads` folder (or to an internal temporary file for immediate viewing) without touching the disk unencrypted if possible.

## Database Encryption
The local metadata database (`zerogram_vault.db`) contains sensitive metadata (original file names, folder structures). When the vault is locked, this database file is itself encrypted. It is only decrypted into a temporary RAM-backed or secure internal storage location while the vault is unlocked.
